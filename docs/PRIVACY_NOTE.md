# 何を読み、何を書くか（本人向けの整理）

公開用の文書ではない。自分のメールを扱う道具なので、どこに何が残るかを 1 枚にしておく。

結論から。**動くのは本人の Google アカウントの中だけで、外へ出るデータは無い。** メール本文はどこにも保存されず、取り込みの実行中だけメモリに載る。カレンダーに書かれるのは、本人が「登録」を押した候補だけ。

## 読むもの

Gmail の検索（既定は `newer_than:7d` ＋選考キーワードの OR ＋除外送信者・スパムとゴミ箱を除く）に当たったメールだけ。1 回の実行で既定 50 通（設定で最大 200 通まで）。

- **件名・送信者（From）・受信日時** … 台帳に書く
- **本文（プレーンテキスト）** … 抽出のために読む。**一時メモリだけ**で、台帳・ログ・確認画面のどこにも出さない
- 添付ファイルは開かない。HTML 本文も使わない（`getPlainBody()` だけ）
- 検索に当たらなかったメールは 1 通も読まない

## 書くもの

### 台帳スプレッドシート「選考カレンダー台帳」（本人の Drive・非共有）

`候補` シートに 1 行 1 候補で、件名（200 字まで）・送信者・受信日時・媒体・抽出結果（企業名・種別・段階・日時・締切・候補日・場所・会議 URL）・確度・根拠・`messageId`・`threadId`・状態を書く。`処理済みメール` シートには `messageId` と処理日時と結果だけ。

Gmail への戻り先は `messageId` から `https://mail.google.com/mail/u/0/#all/<messageId>` を組んで出す。**リンクを保存しているだけで、メールの中身を写しているのではない。**

### Google カレンダー（本人の既定カレンダー、または `設定` の `カレンダーID`）

本人が「登録」を押した候補だけ。1 件の予定に入るのは、タイトル（種別＋企業名＋段階）・日時（または締切日の終日）・場所・ポップアップ通知と、説明欄の 件名・確度・候補日・締切・場所・会議 URL・Gmail リンク・候補 ID・「選考カレンダーで登録」の行。

**メール本文は説明欄にも入らない。** カレンダーを他人と共有している場合は、この説明欄がその相手にも見える点だけ注意する（既定のカレンダーを共有しているなら、`設定` の `カレンダーID` に非共有のカレンダーを指定するほうが安全）。

## 書かないもの・しないこと

- **メール本文をどこにも保存しない**（台帳・ログ・画面・カレンダーのすべて）
- **メールを書き換えない。** ラベル付け・既読化・アーカイブ・移動・削除・送信・下書き作成をしない。処理済みの記録は Gmail 側ではなく台帳の `処理済みメール` シートに持つ（K-3・K-5）
- **媒体サイト（マイナビ・リクナビ・ONE CAREER・OfferBox・キャリタス・企業マイページ）にアクセスしない。** 取り込み元は Gmail だけ（K-1）
- **外部 API・LLM を呼ばない。** `UrlFetchApp` を書かないことをテストで固定している（K-4・`npm run test:policy`）

## 外に出るもの

**無い。** 外部通信ゼロ。Google 以外のサーバーにデータは行かない。確認画面（Web アプリ）も本人の Apps Script が配信し、**実行ユーザー「自分」・アクセス「自分のみ」**なので、URL を知っている他人でも開けない。

例外になりうるのは 2 つだけで、どちらも本人の操作の結果。①カレンダーを他人と共有している場合、登録した予定は共有相手に見える。②較正のために `tests/fixtures/real/` へ置いた実メールは、本人の Mac のディスクにある（`.gitignore` 済みで git には入らない。較正が終わったら消す）。

## スコープ 4 つの理由

| スコープ | 何に要るか | 外したらどうなるか |
|---|---|---|
| `gmail.readonly` | メールを検索して件名・送信者・本文を読む | 取り込みができない（この道具の中心） |
| `calendar.events` | 押した候補を予定として作る・取り消しで削除する | 候補は台帳までで止まり、カレンダーに入らない |
| `spreadsheets` | 台帳を作って読み書きする | 候補を置く場所が無い |
| `script.scriptapp` | 自動取り込みのトリガーを作る・消す | 手動で `importMail()` を実行する運用になる |

**`gmail.readonly` に書き込みは含まれない**（送信・削除・ラベル付けは権限として不可）。`calendar.events` ではカレンダーの新規作成と共有設定の変更もできない。Drive 全体・連絡先・他のカレンダー・メールの送信は要求しない。承認画面で 4 つ以外が出たら、貼ったマニフェストが `dist/appsscript.json` と違う。

`gmail.readonly` で GmailApp が動かず `https://mail.google.com/` に差し替えた場合、承認画面の文言は「メールの読み取り、作成、送信、完全な削除」に変わる。**権限は広がるが、コードが呼ぶ Gmail の API は読み取りだけ**（`MailApp`・`sendEmail`・`createDraft`・`addLabel`・`markRead` を書かないことを policy テストで固定している）。文言と実際の挙動が食い違う状態になるので、差し替えたなら `docs/OWNER_TASKS.md` のメモ欄に残しておく。

## 消し方（この順番で）

1. **`deleteTriggers()` を実行**して自動取り込みを止める（以後メールを読まなくなる）
2. **カレンダーの予定を消す**（残しておいてもよい。消すなら確認画面の「取り消す」か、カレンダー側で手で削除。説明欄に「選考カレンダーで登録」の行があるものが対象）
3. **台帳を削除**する（Drive の「選考カレンダー台帳」をゴミ箱へ → ゴミ箱も空に）。これで件名・送信者・抽出結果が消える
4. **Apps Script プロジェクトを削除**する（`script.google.com` のプロジェクト一覧 → 削除）。Web アプリのデプロイも一緒に無効になる
5. **アカウント側で権限を取り消す。** [myaccount.google.com/connections](https://myaccount.google.com/connections)（「サードパーティ アプリとサービス」の一覧）でこのスクリプトを選び、アクセス権を削除する。**4 まででスクリプトは消えるが、承認の記録はここを操作するまで残る**
6. `tests/fixtures/real/` に置いた実メールの JSON を消す（Mac のローカル）

Gmail には最初から何も書いていないので、メール側で消すものは無い。
