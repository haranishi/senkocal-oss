# 選考カレンダー（仮）要件定義 v1 — 選考メールから予定候補を作り、押すだけでカレンダーへ

- 作成: 2026-09-07。OSS版には私用の企画・調査資料を含めない。
- コードネーム `senkocal`。表示名「選考カレンダー（仮）」。正式名称は本人が決める（候補: センコウログ／エントリーログ／シューカレ。商標と取得性の確認が要る）
- 位置づけ: **本人専用・未公開**。Google Apps Script（GAS）を本人のアカウントで動かす。一般公開は扱わない（`gmail.readonly` は restricted scope で CASA 監査が要る＝調査 §3-2）

## 0. 一言と完了条件
Gmail に届く選考案内メールを GAS が読み、企業名・種別・日時・締切を抽出して台帳（スプレッドシート）に候補として置く。本人は Web アプリの確認画面で候補を見て「登録」を押す。押した候補だけが Google カレンダーに入る。媒体サイトは叩かない。自動で入れない。

完了＝Node のテストで「合成メール fixture → 抽出 → 候補 → 予定の組み立て」が通り、モックした GAS サービスで「取り込み → 台帳 → 登録 → 取り消し」の流れが通り、確認画面の E2E（`google.script.run` スタブ）が通り、`npm run build` が貼るだけの3ファイルを出し、UI 採点が 16/20 以上。**実アカウントでの導入（プロジェクト作成・貼り付け・承認・Web アプリ配信・実メールでの較正）は本人作業**（`docs/OWNER_TASKS.md`）。

## 1. スコープ
- やる: Gmail 検索と取り込み（読むだけ）／ルールベースの抽出（種別・企業名・日時・締切・場所・候補日）／台帳（候補・登録済み・無視・ノイズ）／確認画面（一覧・編集・登録・無視・まとめて登録・取り消し）／カレンダー登録（時刻付き・終日・リマインダー）／冪等な再実行／設定シート／貼るだけのビルド／本人向けの較正ツール
- やらない: 媒体サイトへのアクセス／完全自動登録／メールの書き換え（ラベル・既読・アーカイブ）／メール送信／LLM や外部 API での解析／ES 本文の管理（それは esfill）／一般公開・OAuth クライアント作成／複数アカウント／iCal 書き出し

## 2. 設計制約（企画・調査から。テストで固定する）
| # | 制約 | 固定方法 |
|---|---|---|
| K-1 | 媒体サイトを叩かない。取り込み元は Gmail だけ | policy: 出荷コードに `UrlFetchApp`・`fetch(`・媒体ドメインへの HTTP アクセスが無い |
| K-2 | 自動で登録しない。カレンダーに書くのは本人が「登録」を押した候補だけ | 設計（`importMail` はカレンダーに触れない）＋unit（取り込み経路で `CalendarApp` のモックが呼ばれない） |
| K-3 | メールは読むだけ。ラベル・既読・アーカイブ・送信・下書きをしない | policy（`addLabel`・`markRead`・`moveTo`・`sendEmail`・`createDraft`・`MailApp` を書かない）＋スコープを `gmail.readonly` に限定 |
| K-4 | 本文を外に出さない。LLM・外部 API を使わない | policy（`UrlFetchApp`・API キー・`openai`・`anthropic` 等の語が無い） |
| K-5 | 処理済みの記録はメールに付けず台帳に持つ（K-3 の帰結） | 設計（`処理済みメール` シート） |
| K-6 | スコープは明示・最小: `gmail.readonly`・`calendar.events`・`spreadsheets`・`script.scriptapp` | policy（`appsscript.json` の `oauthScopes` が集合として厳密一致） |
| K-7 | 1 回の実行は 6 分以内に終わる（GAS の上限）。取り込みは 1 回あたり最大 `MAX_MESSAGES_PER_RUN`（既定 50）通 | unit（上限で打ち切り・次回に続き） |
| K-8 | 日時の解釈はホストのタイムゾーンに依存しない（JST 固定・ISO 文字列で持つ） | unit（`TZ=UTC` で走らせても同じ結果） |
| K-9 | fixture に本人の実メールを入れない（合成データのみ）。実メールの較正は gitignore 済みの `tests/fixtures/real/` で本人がローカル実行 | `.gitignore`＋README |
| K-10 | 貼るだけで導入できる（clasp 不要）。`dist/` の3ファイルで完結し、`import`／`export`／`require` を含まない | policy（`dist/Code.gs` を grep） |

## 3. 機能要件（P0=MVP必須、P1=あれば出す）
| ID | P | 要件 | 受け入れ条件 |
|---|---|---|---|
| FR-01 | P0 | 取り込み `importMail()` | 設定から Gmail 検索クエリを組む（`newer_than:<日数>d`＋キーワード OR＋除外送信者）。スレッドを新しい順に走査し、`処理済みメール` に無い message id だけを `parseMail` に渡す。候補は `候補` シートへ、ノイズは状態「ノイズ」で残す（消さない＝見逃しを本人が確認できる）。1 回に最大 50 通、超えたら次回に続き。実行時刻・処理件数を `設定` の `最終実行` に書く。カレンダーには触れない（K-2） |
| FR-02 | P0 | 種別分類 `classifyMail` | 種別＝`seminar`（説明会・セミナー・座談会・インターン案内）／`es_deadline`（ES・エントリーシート・応募締切）／`test_deadline`（Webテスト・適性検査・SPI の受検締切）／`interview`（面接・面談・グループディスカッション。`stage` に 1次／2次／3次／最終／カジュアル）／`schedule_request`（日程調整・希望日の選択・候補日）／`result`（合否・内定・選考結果・お祈り）／`change`（日時変更・中止）／`other`。ノイズ判定＝メルマガ・広告・スカウト DM・システム通知・英語のみ。判定語はデータとして export し unit で網羅。**例外**: `result` でも本文に `interview` の語と受信日より後の日時があれば `interview` 候補を立てる（「1次面接通過のご連絡と2次面接のご案内」は日本の新卒選考で普通）。ノイズは「件名にノイズ語」だけで決めず、**本文からも種別が取れず日時も無い**ときに限る（スカウト経由で決まった面談案内を落とさない） |
| FR-03 | P0 | 日時の抽出 `parseDateTimes` | 対応表記: 「2026年3月5日（木）14:00〜15:00」「3月5日(木) 14時〜」「3/5（木）13:30-14:30」「3月5日 午後2時」「14時半」「正午」「終日」「10:00～（受付9:45）」「2026.3.5」「2:00 PM」「PM2時」（後置の AM/PM も読む）「24時〜29時」（翌日 0:00〜5:00・確度は medium。30 時以上は終日）「10時〜12時、13時〜15時」（1 行 2 枠は 2 件）。年が無ければ受信日から**直近の未来**に推定し、曜日が書いてあれば一致する年を優先（不一致は確度を下げる）。終了が無ければ `end: null`（登録時に既定 60 分）。全角は NFKC で正規化。複数の日時が「第1希望」「候補」「いずれか」「もしくは」「または」「どちらか」「or」の文脈で並べば `choices` にまとめ、単一の予定にしない（**種別が `interview`／`seminar` でも同じ**＝候補の `kind` を `schedule_request` に差し替えた 1 候補にする。メールの分類は元のまま。ただし「または」「もしくは」「どちらか」「or」は、返信を求める語（ご都合・ご希望・お知らせください・お選び・お願いします・第N希望・候補日・いずれか）が同じ行か前後 1 行にあるときだけ候補日の文脈とする＝「3/5 または 3/6 に開催します」は告知なので予定にする。同じ行（または「・」「と」「または」「、」で並ぶ同じ句）に日付が複数・時刻が 1 組のときは、時刻を各日付に配って日付ごとの候補にする＝複数日程の説明会を落とさない）。受信日より前の日時は `isPast: true` を付け、曜日一致だけで過去年を採るときは確度を medium 以下にする |
| FR-04 | P0 | 締切の抽出 `parseDeadlines` | 「締切：3月10日（火）23:59」「3月10日まで」「3/10 正午必着」「3月10日（火）17:00 締め切り」「期限」「提出期限」「本日中」「明日中」（受信日基準）。**「まで」は日時の直後に付くときだけ締切語とみなす**（「これまで」「あくまで」「今まで」は締切語ではない）。**締切語 1 つに対して締切は 1 つ**＝同一行なら最も近い日時、無ければ直後 2 行の最初の日時。予定の語（`面接|面談|説明会|開催|日時|会場|集合`）の扱いは**同一行では句単位**（`、。，；` で区切り、日時より前に予定の語があり、そのあとに締切語が無い句の日時は除く＝「締切 3/10、面接 3/15」は締切 3/10）、**別の行では行単位**で除く。相対表現（本日中・明日中）も時刻無しの締切と同じ扱い（23:59・`allDay: true`）。時刻が無ければ 23:59 とみなし `allDay: true`。締切語の近傍（**同一行か直後 2 行**。前の行は含めない＝直前にある面接日時を締切と誤るため）にある日時だけを締切にする |
| FR-05 | P0 | 企業名 `extractCompany` | 優先順＝①From の表示名（「株式会社◯◯ 採用担当」→「株式会社◯◯」。人事部・新卒採用チーム・採用事務局を除く）②件名の【】「」内 ③本文冒頭の「◯◯株式会社です／でございます」④署名ブロック。From が**ナビ媒体**（`mynavi.jp`・`rikunabi.com`・`onecareer.jp`・`offerbox.jp`・`career-tasu.jp`）なら①を使わず②③④。**ATS**（`i-web.jp`・`axol.jp`・`sonar-ats`）は企業自身が使うので、表示名に媒体名が無ければ①を信用する。英語の役職語（Recruiting・HR・Talent Acquisition・Careers・No Reply）も除く。取れなければ `null`（画面で「企業名を入力」）。株式会社／（株）／㈱の表記ゆれを正規化。媒体名は `media` に別に持つ |
| FR-06 | P0 | 候補の組み立て `parseMail` | 1 通から 0〜n 件の候補。`seminar`／`interview`／`change` は日時ごとに 1 件、`es_deadline`／`test_deadline` は締切ごとに 1 件（締切の行の語で種別を決める＝`テスト|適性検査|SPI|玉手箱|受検` → test、`ES|エントリーシート|応募書類|履歴書|提出` → ES。予定側も `説明会|セミナー|座談会` → seminar、`面接|面談` → interview に行の語で付け替える。付け替えは「締切どうし」「予定どうし」の中だけで、族をまたがない）、`schedule_request` は `choices` と返信期限で 1 件、日時も締切も取れない `seminar`／`interview`／`change` は `confidence: "low"` の 1 候補（`start` 空）として残す（中止連絡の見落とし防止）。`result`／`other`／ノイズは候補を作らず状態だけ残す。各候補＝`{id, messageId, threadId, receivedAt, company, media, kind, stage, title, start, end, allDay, deadline, choices, location, url, subject, confidence, reasons, status}`。`confidence` は high／medium／low（日時が明示・企業名が From から取れた＝high、推定を含む＝medium、片方欠け＝low） |
| FR-07 | P0 | 台帳（スプレッドシート） | シート `候補`（1 行 1 候補・見出し固定・状態＝候補／登録済み／無視／ノイズ／エラー）、`設定`（キーと値: 検索日数 7・キーワード・除外送信者・カレンダーID 空＝既定・締切リマインダー分 900・予定リマインダー分 60,1440・実行間隔時間 2・1回の上限 50・最終実行）、`処理済みメール`（messageId・処理日時・結果）。`setup()` が無ければ作り、あれば見出しだけ検証する。本人がシートを直接編集して状態を「登録」にした行は、**取り込みとは別の関数 `registerMarked()`** で拾う（`importMail` はカレンダーに触れない＝K-2。Web アプリが無くても手動実行で運用できる） |
| FR-08 | P0 | 確認画面（Web アプリ・`doGet`） | 状態＝`loading`／`empty`（候補なし）／`list`／`error`（未設定・権限・通信）。一覧は「日時のある候補（近い順）」「締切」「日程調整（要返信）」「要確認（推定を含む）」「ノイズ（折りたたみ）」に分ける。1 枚＝日時（最大）・企業名・種別チップ・件名 1 行・確度（文言＝明記／一部推定／要確認）・「Gmail で開く」（`target="_blank"`）・編集（タイトル・開始・終了・締切・場所を直接編集）・「登録」（主）・「無視」（文字）。上部に「明記の N 件をまとめて登録」（確度: 高・企業名あり・日時または締切あり・日程調整と変更を除く・過去日を除く）。登録後は行が「登録済み」に変わり「カレンダーで開く」（該当日のカレンダー URL）と「取り消す」。幅 390 で崩れない（スマホで確認する前提）。`google.script.run` の引数と戻り値は ISO 文字列と JSON だけ（`Date` は渡せない） |
