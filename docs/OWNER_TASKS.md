# 本人だけができる作業（この順番で）

AI 側は Google のサービスに触れない。Apps Script のプロジェクト作成・承認・Web アプリ配信・実メールでの較正は、すべて本人の手作業になる。①〜⑤で動く状態になり、⑥⑦は後回しでよい。

所要の見積り（実測ではない）: ①20 分・②5 分・③5 分・④60〜90 分（10 通ぶん）・⑤1 週間の様子見。

## ① 貼り付けと承認

手順は `README.md`「貼り方」の 1〜5（新規プロジェクト → `dist/Code.gs` → `index` に `dist/index.html` → マニフェスト差し替え → `setup()` を実行して承認）。

承認で `gmail.readonly` が拒否されたときは、README「`gmail.readonly` で承認に失敗したとき」の差し替え（`https://mail.google.com/` に変えて再承認）を行い、**どちらで通ったかをこのファイルの末尾にメモする**。設計時点で未確認の項目で、答えが出るのはここだけ。

## ② 台帳の確認

1. Drive に **「選考カレンダー台帳」** ができているか（`setup()` の実行ログに URL が出る）
2. シートが 3 つあるか（`候補`・`設定`・`処理済みメール`）。`候補` の見出しは 24 列
3. `設定` の値を見る。既定は 検索日数 7・締切リマインダー分 900（前日 9:00）・予定リマインダー分 60,1440・実行間隔時間 2・1回の上限 50・予定の既定長さ分 60・カレンダーID 空（＝既定のカレンダー）
4. `importMail()` を手で 1 回実行し、`候補` シートに行が入るのを見る（0 件なら `設定` のキーワードと検索日数を疑う）

検索は `newer_than:<検索日数>d` なので、**トリガーを 7 日以上止めるとその間のメールは検索の外に出て、二度と拾われない。** 長く止めたあとに再開するときは、`検索日数` を一時的に伸ばして（上限 30）1 回取り込み、終わったら 7 に戻す。

## ③ Web アプリ配信

README「貼り方」の 7。**実行ユーザー「自分」・アクセスできるユーザー「自分のみ」**を必ず確認する（ここを「全員」にすると URL を知っている人が本人の候補を読める）。出た URL をスマホのホーム画面に追加して、390 幅で崩れないかを実機で見る。

コードを直して貼り替えたときは、**「デプロイを管理」から既存のデプロイを編集してバージョンを「新バージョン」にする**。新しいデプロイを作ると URL が変わり、ホーム画面のアイコンが古い版を指したままになる。

## ④ 実メールでの較正（いちばん効く作業）

合成 fixture 41 通は AI が作ったもので、実物の書き方とは違う。**合成で全件通っていても実メールでは外れる。** 抽出の当たり外れを決めるのはここ。

1. Gmail で選考メールを **10 通**選ぶ（媒体をばらけさせる。マイナビ・リクナビ・ONE CAREER・企業の直メール・ATS 経由を各 2 通ずつが目安）
2. 各メールの**本文をコピー**して `tests/fixtures/real/<番号>.json` に置く。「メッセージのソースを表示」は quoted-printable（`=E3=81…`）で読めないことがあるので、通常表示の本文をそのまま貼るほうが早い。このフォルダは `.gitignore` 済み（K-9）

```json
{
  "id": "18f3ab0c1d2e3f45",
  "threadId": "18f3ab0c1d2e3f45",
  "from": "株式会社◯◯ 採用担当 <recruit@example.co.jp>",
  "subject": "【1次面接のご案内】",
  "date": "2026-03-01T10:12:00+09:00",
  "body": "この度は…\n日時：3月5日（木）14:00〜15:00\n会場：本社 3F"
}
```

`date` は受信日時で、**`+09:00` を必ず付ける**（年の推定に使う）。`body` はプレーンテキスト、改行は `\n`。

3. `npm run calibrate` を実行する。1 通 1 行の表で、件名・種別（段階）・企業名・開始・締切・確度・候補件数が出る
4. 表を下の記録表に写し、外れた項目に × を付ける
5. **× が 2 件以上**あれば、この記録表を渡して Claude に**「辞書と正規表現の較正」**を頼む（`src/core/` の `KIND_KEYWORDS`・`NOISE_KEYWORDS`・`MEDIA_DOMAINS`・日時と締切の正規表現が対象）。直したら `npm test` を通してから ①の貼り替えへ

## ⑤ トリガー作成と 1 週間の様子見

`createTrigger()` を実行（`設定` の実行間隔・既定 2 時間ごと）。止めるときは `deleteTriggers()`。

1 週間、毎朝の確認をこの 2 つでメモする。

- **誤登録**（間違った日時・企業でカレンダーに入った件数）＝ **0 でなければ較正に戻る**。行った先で予定が無い事故のコストは、見逃しより高い
- **見逃し**（Gmail には来ていたのに候補に出なかった件数）＝ 台帳の `ノイズ` 行と、`処理済みメール` に載っているのに候補が 0 件のメールを数える

見逃しが多いときは、まず `設定` のキーワードを足す（媒体独自の言い方・「WEBセミナー」「マイページ」など）。それでも出ないなら分類の側の問題なので、④の較正に戻す。

## ⑥ 正式名称

`senkocal`／「選考カレンダー（仮）」は仮。候補はセンコウログ・エントリーログ・シューカレ（`docs/01_requirements.md`）。**本人専用のまま使うなら決めなくてよい。** 公開するなら商標と取得性の確認が要るうえ、`gmail.readonly` は restricted scope で CASA 監査が必要になる（公開は現状スコープ外）。
