選考カレンダー（仮） senkocal — 選考メールから予定候補を作り、押すだけでカレンダーへ

仕組み:
  Gmail の選考案内メールを importMail() が読み、企業名・種別・日時・締切を
  ルールベースで抽出して「選考カレンダー台帳」スプレッドシートの `候補` シートに
  1 行 1 候補で置く（メールは読むだけ・本文は台帳に書かない）。
  → 確認画面（このプロジェクトの Web アプリ）で候補を見て「登録」を押す。
  → 押した候補だけが Google カレンダーに入る。自動では入らない。

前提:
  - このスクリプトを動かすアカウントの Gmail・カレンダーだけを見る（本人専用・未公開）
  - 媒体サイト（マイナビ・リクナビ等）には一切アクセスしない。取り込み元は Gmail だけ
  - 台帳が正本。Web アプリは台帳の見え方の一つで、シートを直接直してもよい

使い方（詳細は README.md / docs/OWNER_TASKS.md）:
  1. Apps Script で新規プロジェクトを作り、この Code.gs と index.html を貼る
     （appsscript.json はエディタの「マニフェスト ファイルを表示」で貼り替える）
  2. setup() を 1 回実行 → 承認 → 台帳が作られる（URL がログに出る）
  3. importMail() を手動実行して `候補` シートに候補が入るのを見る
  4. デプロイ → ウェブアプリ（実行者: 自分／アクセス: 自分のみ）→ URL を開く
  5. 候補の日時が合っていれば「登録」。まとめて登録は確度「高」だけが対象
  6. 慣れたら createTrigger() で `設定` の実行間隔（既定 2 時間）ごとに自動取り込み

安全設計:
  - **自動でカレンダーに登録しない。** importMail() はカレンダーに一切触れない
  - **メールを書き換えない。** ラベル・既読・アーカイブ・移動・送信・下書きをしない
  - **外部への通信ゼロ。** 外部 API も LLM も呼ばない。本文は台帳・ログ・画面に出さない
  - スコープは 4 つだけ（gmail.readonly／calendar.events／spreadsheets／script.scriptapp）
  - 同じメールは二度取り込まない（`処理済みメール` シート）。同じ予定は二度登録しない
  - トリガーの二重起動は LockService で直列化する

危険な関数:
  - deleteTriggers() … 自動取り込みを止める（予定は消えないが、以後メールを見なくなる）
  - api_undoRegister(id) … カレンダーの予定を削除する（台帳の状態は「候補」に戻る）
  - 台帳の行を手で消すと処理済みの記録も消える。同じメールが再び候補として並ぶ
